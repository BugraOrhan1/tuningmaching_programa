current repository. Where a test or production-scale reproduction has not yet

## Reproduction status

- **Statically verified:** the refresh query path and GUI-mode database initialization were blocking on the GUI thread. Other UI actions still perform potentially expensive synchronous work; the separate TuningCore has unbounded discovery and pending-row materialization.
- **Runtime reproduction verified:** the heartbeat test failed before the fix because the GUI thread waited on a gated lookup; it passes after moving the refresh snapshot to a worker. A separate test verifies `Service` construction is off the GUI thread and Qt already exists.
- **Production-scale reproduction unavailable here:** this workspace does not contain the user's full 8 TB library, and the Linux container cannot reproduce a Windows-specific native hang. Synthetic tests can verify thread responsiveness and recovery contracts, not Windows/device performance.
- **Not measured:** the documented 1.2M-file time estimates are extrapolations, not a 1.2M OLS run in this environment.

## Changes And Test Status

- The default GUI path shows a startup window while `Service` and the database
  initialize in a worker. CLI/API commands retain synchronous initialization;
  the startup worker is joined when the GUI event loop exits.
- Refresh reads run in a worker; rendering remains on Qt's GUI thread. Dashboard
  counts use SQL counts, identity lists omit members, and UI lists have explicit
  limits. Pattern summaries omit per-pattern members/alignments; ECU-image and
  software-lineage tables are refreshed from the same snapshot. Closing is
  blocked until dashboard advice also completes.
- The A|B workspace exports verified source metadata and analysis findings as
  read-only JSON with a SHA-256 manifest; the API and GUI export no BIN. Pair
  lookups and confirmed-pair chains use indexed, bounded SQL queries.
- TuningCore pending OLS parsing uses keyset pages and one bounded worker pool
  per run. Worker hangs still have no timeout or cancellation recovery.
- `QT_QPA_PLATFORM=offscreen python -m pytest -q tests/test_api_ui.py`:
  **19 passed**. `tests/test_product_suite.py`: **56 passed, 1 skipped**.
- Broad safe suite: **181 passed, 6 skipped, 3 deselected**. `engine/tests/test_engine.py`:
  **10 passed, 1 skipped**. The tune-builder
  test file and three candidate-generation tests were not run because they
  exercise binary candidate generation; high-risk recipe behavior remains
  unchanged and outside this read-only/performance expansion.
- Windows startup, very large real libraries, remaining synchronous UI actions,
